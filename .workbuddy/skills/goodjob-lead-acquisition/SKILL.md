# 外贸搜客获客方法论

你是外贸获客引擎的执行者。任务提示词给出目标市场、行业与输出契约；本技能提供「去哪找、怎么构造检索、怎么证明这家企业真实存在、什么时候算找够了」。

三原则：**契约优先、证据说话、绝不编造**。

**本技能只规定搜索与核实方法，不改变输出结构**；所有机制都是内部步骤，契约里没有的字段一律不输出。

## 0. 契约优先（最高优先级）

- 任务提示词定义的输出格式、字段名、语言、数量限制具有最高优先级。
- 若任务给出**增量行协议**（以 `@@FOUND@@` 作为行首标记），则**每核实并确认一家企业，立即单独输出一条该标记行**——它是管道实时入池的触发器，攒到任务尾部批量输出等于没有增量。
  - 每行必须**在一行内写完**：不换行缩进、不加代码栅栏、不加解说。
  - 字段名严格照任务提示词给出的写法，**不自行创名、翻译或改同义词**。
  - 增量行与最终汇总可能并存，互不替代：任务要求汇总时，末尾仍须输出完整汇总。
- 管道任务不做过程解说，不输出契约外的寒暄、标题或解释。

## 1. 渠道矩阵

### 1.1 六类来源（按可信度与产出顺序）

| 类别 | 作用 | 可信度 | 典型入口 |
| --- | --- | --- | --- |
| ① 企业注册与法人登记 | 证实**实体存在** | T0 最高 | 各国工商/法人登记库（见 1.2） |
| ② 海关与贸易数据 | 证实**进出口行为** | T0（官方统计）/ T2（提单类） | UN Comtrade、各国海关公开统计、提单数据服务 |
| ③ 行业协会与商会 | 补**本地会员名单**，比英文搜索更全 | T1 | 越南 VCCI、印尼 KADIN、印度 CII/FICCI、土耳其 TOBB、巴西 CNI 等 |
| ④ 展会官方参展商名录 | 证实**在营 + 采购活跃** | T1 | 广交会、Big 5、Hannover Messe、Ambiente、Automechanika 等（按行业选） |
| ⑤ 企业官网与独立站 | 补**产品线、产能、联系方式** | T1（自述） | 由搜索结果定位 |
| ⑥ B2B 平台与黄页目录 | 只用来**发现候选** | T2/T3 | Alibaba、Made-in-China、Global Sources、Europages、Kompass、各国黄页 |

**硬规则**：①–④ 才能作为核实证据；⑤ 属企业自述，可用于业务匹配但不得单独作为实体存在证明；⑥ **只能产出候选**，不能作为核实依据。

### 1.4 每类来源怎么用、坑在哪

| 来源 | 核实时的正确用法 | 常见坑 |
| --- | --- | --- |
| 注册与法人登记 | 用「法定全称」查，核对注册号与状态（存续/注销） | 同名企业混淆；子公司用母公司注册号；只查英文名查不到本地登记 |
| 海关与贸易数据 | 官方统计证明「有该品类贸易」；提单类只能印证「疑似」 | 把商业数据当官方事实；把「国家贸易总量」当成「某企业有进口」 |
| 协会与商会 | 会员名单用来**补全**名录，顺带确认在营 | 会员名单常年不更新；把「曾经的会员」当现状 |
| 展会名录 | 参展记录证明「在营 + 有对外采购/销售意愿」 | 往届名录被当当年；把「观众证」当参展商 |
| 企业官网 | 取产品线、产能、联系方式的**自述**口径 | 官网堆砌全品类；只做 landing page 无实质内容；域名是经销商而非厂方 |
| B2B 平台 / 黄页 | **只用来发现候选**，随后必须回到 ①–④ 核实 | 把平台页面当官网；把平台上的贸易公司当终端买家 |

**核实时的四类典型误判**（逐条自检）：
1. 把**贸易商**当成制造工厂（对方只做转手，不是终端需求方）；
2. 把**经销商/代理商**当成最终用户；
3. 把**同类产品的竞争厂商**误当成潜在客户（除非任务目标是找渠道商）；
4. 把**仅存在于平台列表**的公司当成真实在营实体。

## 2. 检索式构造公式

不要用「国家 + 行业」泛搜。按下面的骨架拼检索式，逐项替换后再交给搜索引擎：

- **行业项**：本地语行业词 OR 英语行业词（至少各一个）
- **角色项**：工厂/制造商/供应商 词 OR 进口商/批发商/经销商 词
- **地域项**：国家 OR 产业集群城市 OR 工业园区 OR 港口名
- **主体项**：企业形式词（Co., Ltd. / GmbH / Sdn Bhd / TNHH / Pte Ltd / S.A. / LLC）
- **排除项**：招聘 / 二手 / 维修 / 零售店 / 价格比较

五项交叉组合成一条检索式（`AND`/`OR` 按搜索引擎实际语法展开，不要照抄符号）。

- **先市场后企业**：先确认目标国的行业聚集地（产业集群、工业园区、出口口岸城市），再往企业层搜，命中率远高于泛搜。
- **多语言多轮**：同一目标至少跑「商务英语 + 当地官方语言」两路；必要时加第三路（殖民语言或邻国语言）。
- **同义词轮换**：每轮换一组同义行业词，避免结果高度重叠（重叠本身就是「已饱和」的信号）。
- **排除词要显式写进检索式**：招聘、二手交易、维修服务、零售门店、比价站会大量污染结果。

## 3. 两轮制：Discovery → Verification

| 轮次 | 目标 | 产出 | 禁止 |
| --- | --- | --- | --- |
| **第一轮 Discovery** | 广撒网，铺候选名单 | 公司名 + 来源页 + 初步业务印象 | 不得把候选当作已核实结果交付 |
| **第二轮 Verification** | 逐家过核实证据链 | 置信度、官网、主营、匹配度 | 不得跳过核实直接给高置信度 |

**结果轮次间漂移是正常的**：同一市场不同任务轮次会返回不同企业（搜索索引与排序实时变化）。只报告**本轮实际核实到**的企业；不要为凑数复述记忆里旧任务的企业，也不要因为「上次见过」就跳过核实。

## 4. 企业核实证据链（每家候选逐条走，能走多远走多远）

1. **官网可达性**：能否访问？内容是否与行业匹配？有无产品页/工厂信息/联系方式？纯 landing page 且无实质内容 → 降级。
2. **实体存在性**：注册登记、海关编码、商会会员、展会参展记录等**任一权威来源**可印证。
3. **业务匹配度**：产品线、客户类型、进口/采购行为是否与任务目标匹配（例如找涂料厂，要确认它**生产**涂料而非仅零售）。业务简介写成「主营产品 + 客户类型 + 出口行为」三要素；只写核实到的事实，不写「领先的」「专业的」这类推测性定位语。
4. **规模与活跃度**：成立年限、员工规模、近期活动（展会、新闻、招聘）——用于判断是否值得触达。

## 5. 决策人 / 采购人邮箱（CRM 硬门槛）

CRM 只接收**能指名到人**的买方联系人：一位**决策人**或**采购人**，并且有他/她的公开工作邮箱。
拿不到就**不报这家企业**——零结果是合格结果，一堆只有 info@ 的公司不是。

**先找人，再找邮箱**（顺序反了就会退回部门信箱）：

1. 找人的页面优先级：官网 `team / leadership / management / about / our-people` → 联系页里的姓名+职务 → 展会参展商名录的联系人 → 商会/协会会员名录 → 新闻稿、招标公告里的项目联系人。
2. 决策人关键词（任一语言）：owner / founder / co-founder / CEO / chief executive / managing director / general manager / president / partner / proprietor / chairman；中文 总经理 / 董事长 / 总裁 / 老板 / 创始人；其余本地语见职位原文（如 Geschäftsführer、Directeur Général、Gerente General、Tổng Giám đốc、Genel Müdür）。
3. 采购人关键词：procurement / purchasing / sourcing / buyer / supply chain / import manager；中文 采购 / 采购经理；本地语 Einkauf、Achats、Compras、Acquisti、Satın Alma、Mua hàng、Purchasing、Pembelian。
4. **不收**：`info@` `sales@` `contact@` `export@` `office@` 这类部门信箱；`purchasing@` `procurement@` 这类采购部公共信箱同样**不算人**。`Sales Director` / `Marketing Manager` 属于对外销售侧，也不是买方决策人。
5. **绝不猜邮箱格式**（`firstname.lastname@`、`j.smith@`、`info+name@`）。只报你在页面上**亲眼看到**的地址；看不到就换页面/换来源，再没有就放弃这家。
6. 每条联系人都要带 `sourceUrl`（你看到姓名 + 职务 + 邮箱的那个页面）与角色 `role`（`decision_maker` / `purchasing`）。同一家公司有多位时都给出，角色不要混。

## 6. 企业身份唯一性判定（防同名/集团串证据）

报告前对每家企业自问，**任一命中都要处理**：

1. **同名不同国**：国家字段必须如实填写；不同国家的同名企业是**不同候选**。
2. **集团与子公司**：母公司的产能、认证、客户**不能**写成子公司的。
3. **同一集团不同国子公司**：按公司实体计为**不同候选**（除非任务另有说明）。
4. **改名前后的同一主体**：以现行法定名称为准，旧名写进证据来源。
5. **多域名同企业**：选证据最充分的主域名，其余域名写进证据来源，**不重复报告**。
6. **品牌名 ≠ 法定名**：公司名按来源**法定全称**填写（含 Co./Ltd./TNHH/GmbH 等后缀），CRM 会自动归一化比对；不要自行缩写或翻译。

中文/非拉丁字符的公司名按来源原文保留，不翻译改写。

## 7. 置信度量化（替代主观分级）

按分值表累加后对号入座，**不要为了凑高分把同一来源换个说法重复计数**：

| 证据 | 分值 |
| --- | --- |
| 官网可达且内容与业务明确匹配 | +2 |
| 注册/法人登记可印证实体 | +3 |
| 海关或官方贸易数据印证进出口行为 | +3 |
| 行业协会/商会名录出现 | +2 |
| 展会官方参展记录出现 | +2 |
| 产品线与目标品类直接对口 | +2 |
| 找到公开的采购/进口线索（招标、采购公告等） | +1 |
| 仅有目录站/平台列表，无其它印证 | −2 |
| 与目标业务明显不符或存疑 | −3 |

| 总分 | 档位 | 处理 |
| --- | --- | --- |
| ≥8 | high | 可交付为高置信候选 |
| 5–7 | medium | 交付但标明缺哪类印证 |
| ≤4 | low | 可以报告，但必须如实标注低置信度 |

契约以数值字段表达置信度时，按其取值范围折算，**换算规则要在心里一致**，不要把「分数」当「档位」写。

## 8. 饱和判定（什么时候算找够了）

满足**任一**条件即可收工：

- 连续 **2 轮**更换同义词后检索，**没有新增可核实企业**；
- 已覆盖 ①–④ 类来源中的**至少三类**；
- 新增结果与已有结果高度重合（同一批域名/同一批企业再次出现）。

零结果时**如实报告**并说明已尝试的搜索方向与语言，不要用编造企业充数。

## 9. 去重分工（CLI 与 CRM 的边界）

- 你只负责**任务内**去重：同一公司实体无论从几个来源、几个域名发现，只报告一次，字段取证据最全的版本。
- 与存量候选池/线索/客户的去重由 **CRM 自动完成**（证据记录 → 域名+国家 → 归一化公司名+国家 三级键）。你**不需要也无法**查询存量池——不要为了「避免重复」而漏报企业。
- **你的判定口径要和 CRM 一致**，否则会出现「你合并了、CRM 认为是两家」或反之：
  - 主键是**域名 + 国家**：同一家公司的不同国家站点（`jotun.co.th` / `jotun.co.jp`）**是两家候选**，分别报告，不要合并；
  - 次键是**归一化公司名 + 国家**：法律后缀（Co., Ltd. / GmbH / Sdn Bhd / TNHH / Pte Ltd / S.A.）与括号、大小写不构成差异，同名同国家就是同一家；
  - **国家字段缺失时保守不合并**：宁可报告两条，也不要把不同国家的同名企业并成一家。
- 判定顺序上有个反直觉但重要的点：**先判「是不是同一实体」，再判「值不值得报」**。不要因为嫌重复而在检索阶段就跳过某家公司——**该由 CRM 去重，不该由你漏报**。
- 若同一批任务里某家公司被多个来源反复命中，**这本身就是置信度加分依据**（多渠道印证），而不是重复条目：合并成一条，把多条来源写进证据。

## 10. 交付前 Gate（逐条过）

1. 每条候选是否有**官网可达性或权威来源**支撑其存在？纯目录站来源的是否已标 low？
2. 每条候选是否都有一位**具名的决策人或采购人 + 公开邮箱**？只有 info@/sales@ 的必须整条删掉（这是 CRM 的硬门槛，不是加分项）。
3. 邮箱是否**亲眼看到**而不是按格式拼出来的？每条联系人的 `sourceUrl` 是否指向能看到姓名+职务+邮箱的页面？
4. 置信度是否按分值表算出，而不是凭感觉给？
5. 公司名是否为来源中的法定全称？国家字段是否如实？
6. 是否有把集团母公司资料写成子公司事实的句子？
7. 有增量行协议时，增量行是否**逐家即时输出**、一行写完、字段名与提示词完全一致？
8. 最终汇总是否完整输出（若契约要求）？
9. 是否出现了契约之外的内容（Markdown 包裹、过程解说、寒暄）？
10. 若零结果，是否说明了已尝试的方向与局限？

## 11. 反编造红线

- 公司、网站、联系方式、认证、成立年份、规模数字一律**不得编造或脑补**；来源里没有就不写。
- 网站只写实际确认可达的；不确定时**宁可不填**。
- 不把「同名公司」的证据挪给另一家（尤其集团与子公司、不同国家的同名企业）。
- 不登录、不绕付费墙、不抓取领英等社交平台。
