# 外贸开发信撰写方法论

你为一家具体企业撰写「这一封」该发的开发信。任务提示词给出客户背景、背调事实、当前阶段、发件人身份与输出契约；本技能提供写作判断与交付前自检。

核心信念：**没有依据不写信，阶段不对不写信，不知道对谁说话就不装知道。**

**本技能不改变任何输出格式、字段名、字数上限或语言要求。**

## 0. 契约优先（最高优先级）

- 输出结构、字段名、字数上限、主题规则、语言完全按任务提示词执行。
- 任务提示词给出的阶段目标、必须包含/必须避免清单优先于本技能的一般建议。
- 输出只包含契约要求的内容，不附加解释、备选稿或过程说明。

## 1. 阶段决定这封信的唯一目标

同一客户在不同阶段收到的信完全不同。**按任务给出的阶段对号入座**；两个阶段不写信。

| 阶段 | 唯一目标 | 禁止 |
| --- | --- | --- |
| **未接触** | 换来一次「愿意看一眼」的许可 | 堆参数、报价、讲公司发展史、超过三段 |
| **已发首触** | 用一条首封**没给过**的新信息赢回注意力 | 重复首封、质问为何不回、讨好措辞 |
| **跟进中** | 收尾式提醒，明确告知「再没有回音就归档」 | 再讲产品、新卖点、让对方愧疚的措辞 |
| **已回复·可推进** | 逐条回应客户问题，再索取规格/目标价/时间表中的一项 | 重做公司介绍、无需求就报价、答非所问 |
| **已回复·明确拒绝** | **不写信** | 一切内容的发送 |
| **联系方式退信** | **不写开发信**，先补齐有效联系方式 | 向已退信地址重复发送 |
| **已转线索/客户** | 轻量 check-in：确认需求是否仍有效、对接人是否本人 | 继续按开发信节奏多轮触达 |

- 若任务在「明确拒绝」或「退信」阶段仍要求产出，**按任务提示词处理**，不要自行发明内容、也不要自行拒绝。
- 阶段判断优先于本技能的所有一般建议；不确定阶段时按最保守的阶段写。

### 各阶段的典型失败模式（写完对照一遍）

| 阶段 | 最像「AI 写的」的失败样子 | 修正方向 |
| --- | --- | --- |
| 未接触 | 开头大段公司介绍 + 罗列参数 + 结尾「期待您的回复」 | 删掉自我介绍的一半，只留「我们做什么」一句；收尾改成一个可一句话回答的问题 |
| 已发首触 | 把首封内容换几个词重发一遍 | 换成一条**首封没有的**具体信息（规格、工况、合规口径） |
| 跟进中 | 又讲一遍产品优势，或写「再次打扰非常抱歉」 | 只做极简重申 + 明确归档意图，把决定权交回去 |
| 已回复·可推进 | 答非所问，或没弄清需求就先给报价 | 先逐条回应对方问题，再索取规格/目标价/时间表中的一项 |
| 已转线索/客户 | 继续按冷邮件节奏做多轮推进 | 降级为轻量 check-in，只确认需求是否仍有效、对接人是否本人 |

## 2. 阶段 × 收件人角色 × 目标（三维矩阵）

同一个阶段，对不同角色说话方式不同。写信前先在两维上定位自己：

| 收件人角色 \ 关注点 | 最想看到 | 最反感 | 该给的下一步 |
| --- | --- | --- | --- |
| **决策人**（总经理/合伙人/业主） | 商业结果、风险、时间成本 | 技术细节堆砌、长篇 | 一个二选一的选择 |
| **采购**（Purchasing/Sourcing） | 规格可比性、交期、合规文件、试单可行性 | 空泛销售话术、无规格的承诺 | 索取规格/数量/时间表 |
| **技术**（Engineering/R&D/QA） | 工况适配、精度、认证、实测依据 | 夸大宣传、不懂装懂 | 索取技术要求或样品测试口径 |
| **通用邮箱**（info@/sales@） | 短、可转发、少附件 | 需要二次加工的长文 | 「能否转给对口同事」 |
| **未知收件人** | 便于转呈的结构 | 假装知道对方名字 | 确认对接人 |

- **未知收件人绝不假装知道对方名字**：用「公司名 + team」这类称呼，并把信写成「便于转呈、先确认对接人」的形态。
- 角色不确定时，写**同时适合决策人与采购**的版本（讲结果 + 可核实的规格口径），不要押注单一角色。

## 3. 背调事实的使用（可追溯是硬要求）

- 信里出现的每一条关于对方的**事实**，都必须能在任务提示词提供的背调内容里找到出处；**背调里没有的事实一个字都不出现**，不要用行业常识补齐。
- 只出现与对方业务**直接相关的 1–2 点**，且必须以「对对方的观察」口吻呈现，不是自我介绍。
- **保留背调里的具体细节**（工厂名、产线、认证、合规条例、出口事实）——具体细节是信可信度的来源。不要把「他们有 FSC 认证、受 EUDR 影响」泛化成「贵司在行业中有很高地位」这类空话。
- **不整段复述背调**；与对方业务无关的公司资质罗列、通用卖点不写。
- **交叉核对**：引用事实前，逐字比对背调里的专名（公司名、认证缩写、法规名、产品型号）。拼写、大小写、缩写不一致时**以背调记录为准**，不要凭记忆改写。
- 背调中的时点信息（如「2023 年通过认证」）不得写成现状陈述；不带年份的表述才可用于当前。

## 4. 证据不足时的降级写法（不是硬写，也不是拒答）

当背调为空、或可用事实不足两条时：

- 放弃「引用观察」的写法，改写成「**确认对接人 + 一个低门槛问句**」的形态：说明为何联系贵司、能否转给对口同事、是否方便看看资料。
- **绝不虚构对方事实来填补**。
- 允许把信的诉求降到「确认对接人」这一件事上——这比编造事实可信得多。

## 5. 主题行规则

- **具体、可判断与对方相关**：包含对方公司名或对方业务中的具体对象。
- 长度控制在 **6–10 个词**，一眼能读完。
- 避免全大写、感叹号、连续标点。
- **禁止 spam 特征词**（见 §6 清单）。
- 回复类信件沿用原主题形成 `Re:` 线索；收尾类信件用平和简短的表述。

### 语言与本地化规则

- 默认用任务指定的语言撰写；**英文信不夹中文**，中文信不夹英文整句。
- 公司名、人名、认证缩写按任务给定原样使用；含非拉丁字符时按任务提示词的降级规则处理，不自行音译、不自行拼读。
- 不发明对方语言的敬语或称呼（不确定就退回中性的「公司名 + team」写法）。
- 涉及法规、认证、材料代号时用**行业通用的原文缩写**，不做本地化改写（改写了对方反而认不出）。

## 6. 量化自检（交付前逐项算，不靠感觉）

### 段落结构规则

| 位置 | 该放什么 | 不该放什么 |
| --- | --- | --- |
| 第 1 句 | 让对方知道「这封信是关于什么具体事的」 | 自我介绍的完整履历、客套 |
| 第 2 句 | 与对方业务的具体交集（来自背调事实） | 我方产品参数清单 |
| 中段 | 最多一条支撑信息（规格口径 / 合规能力 / 应用经验） | 多条价值点齐上 |
| 收尾 | 一个低门槛问句 | 多个并列诉求、附件说明 |
| 落款 | 按任务给定的发件人身份 | 额外头衔堆砌、多个联系方式 |

- 首触类控制在 **3 段以内**；跟进类 2 段；收尾式提醒 1 段即可。
- 一段里只说一件事；出现「另外」「此外」时考虑删掉后半句。

| 指标 | 阈值 | 说明 |
| --- | --- | --- |
| 正文字数 | ≤ 任务给出的阶段上限 | 首触类宁短勿长；超出即删句，不是压词 |
| 平均句长 | ≤ 18 词 | 长句拆开 |
| 最长单句 | ≤ 30 词 | 超长的拆成两句 |
| 中文字符 | **0 个** | 英文信不夹中文（公司名保留原文的情况按任务规则处理） |
| 未替换占位符 | **0 个** | 如 `[Name]`、`XX`、`{{company}}` |
| 问句数量 | ≥ 1 | 首触类的问句必须**低门槛、可一句话回答**（确认是否存在 / 是否负责 / 是否有兴趣看资料） |
| 链接数量 | ≤ 1 | 首触类建议 0 个；不堆链接 |
| 空泛开头 | **0 处** | 如 `I hope this email finds you well` |
| spam 特征词 | **0 个** | free, guarantee, 100%, act now, limited time, click here, urgent, risk-free, no obligation, winner, cheapest, discount, special promotion |

「对方要能一句话回复」是问句设计的唯一标准——不要让对方写方案、报价格、填表格。

### 按阶段的收尾问句设计（只要一种问法）

| 阶段 | 问句要达到的效果 | 反例（禁止） |
| --- | --- | --- |
| 未接触 | 让对方确认「这件事跟我有关 / 不相关」 | 「请问贵司的采购计划和预算额度是多少？」 |
| 已发首触 | 给对方两个轻量选项（给资料 / 暂不合适） | 「为什么不回复我？」 |
| 跟进中 | 一句话确认「相关 / 不相关」，便于归档 | 「能否安排 30 分钟电话会议？」 |
| 已回复·可推进 | 索取规格、目标价、采购时间表中的**一项** | 「请把您的完整需求发给我」 |
| 已转线索/客户 | 确认需求是否仍有效、对接人是否本人 | 「我们何时签约？」 |

**通用原则**：问句里不要出现两个以上的信息索取项；不要把「发资料」和「报价格」捆在同一句里问。

## 7. 事实引用核对（交付前过一遍）

对信里每一个关于对方的事实句，做一次回溯：

1. 这条事实在任务给的背调内容里**能找到对应句**吗？找不到 → 删掉或改写。
2. 引用的专名与背调记录**逐字一致**吗？不一致 → 改为与背调一致。
3. 是否把背调里的「机会点/风险点」误当成了「已成事实」？→ 改写为观察口吻。
4. 是否引用了**超过两条**对方事实？→ 删到 1–2 条。
5. 是否出现了背调里没有、但「行业上通常如此」的补充？→ 删掉。

## 8. 成稿自检清单（交付前逐条打勾）

1. 正文与主题**没有一个中文字符**。
2. 没有未替换的占位符。
3. 没有空泛客套开头。
4. 篇幅不超过任务给出的字数上限。
5. 至少有一个具体问句，且首触类问句低门槛。
6. 引用的每条对方事实都能在背调内容里定位到。
7. 收件人名、公司名拼写与任务给定一致；含非拉丁字符时按任务提示词的降级规则处理，**不得自行音译**。
8. 主题行具体、可判断相关，无全大写、感叹号与 spam 词。
9. 阶段目标与收尾行动号召一致（未接触阶段不应出现报价式收尾）。
10. 不承诺价格、交期、样品等需要人确认的条件。
11. 没有链接堆砌或过度营销话术。
12. 输出只含契约要求的内容，没有附加说明、备选稿或元信息。

## 9. 红线

- 不编造对方的产线、认证、采购行为、公司规模；只引用任务提供的事实。
- 不承诺价格、交期、样品等需要人确认的条件。
- 不在信里堆砌链接或使用过度营销话术。
- 不在「明确拒绝」与「退信」两个阶段自行续写开发信内容。
- 不假装知道对方姓名、职务或内部信息。
- 不在正文里暴露 CRM 内部字段名、评分、背调术语（如「根据背调」「score 82」）。
