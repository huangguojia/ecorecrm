## 二、逐点方案与实现

### 1. 已成交客户被归入未成交档案

**根因**：`POST /api/customers` 把 `lifecycleStatus` 硬编码成 `"open"`，前端表单里根本没有「成交状态」这一栏——用户无处可选，后端也只认未成交。列表的「已成交 / 未成交」是按 `hasWonDeal`（`lifecycleStatus === "won"` 或已有 PO）过滤的，所以手动录入的成交客户永远落在未成交页。

**改动**：
- `backend/src/routes/customers.ts`
  - POST / PATCH 入参新增 `lifecycleStatus: z.enum(["open","won"])`
  - 新建：`won` 时清空保护期（成交客户不参与保护期回收）
  - 修改：**仅当状态真的发生变化**时才动保护期，避免「每次编辑都续期」
- `frontend/src/prototype-api.ts`
  - 快速新增表单（默认入口）新增 `quickCustomerLifecycle`
  - 完整表单新增 `customerLifecycleInput`
  - 两处保存都提交 `lifecycleStatus`
  - 从「已成交客户」页进入新增时默认选中「已成交」

**验证**：`POST` 建成交客户 → `lifecycleStatus=won`、`hasWonDeal=true`、`protectedUntil=""`；未成交客户仍有 2 周保护期；`PATCH` 从 open 改 won 生效。界面：在已成交页新增默认 `won`，保存后出现在已成交列表、未成交页看不到。

### 2. 供应商改为仅自己可见

**根因**：供应商列表按 `teamId` 全量返回；而且 `supplier.read` 的 IAM 范围是 `org_unit`，直接套 `canSeeOwner` 会解析出全团队 ownerIds，等于没过滤。

**改动**：
- `backend/src/routes/customers.ts`：新增 `canSeeSupplier()`（本人 / `tenantWide` / admin·manager / 公池），列表、查重、编辑、批量删除全部改用它；查重只在可见范围内做（否则等于告诉业务员「别人有这家供应商」）
- `backend/src/iam/iam-foundation.ts`：`supplier.*` 的 `scopeModes` 补上 `self`
- `backend/src/supplier-repository.ts`：更新设计注释，与新口径一致

**验证**：A 建供应商 → A 见、B 不见、管理员见；B 直接 PATCH 该供应商 → 404（不泄露存在性）。界面：A 列表出现，B 列表为空。

### 3. PO 模板字段无处填写

**根因**：PO 模板的条款表早就画了 `Condition / Warranty / Lead Time` 三栏，但单元格是写死的空 `<td>`；`TradeDocument` 类型、zod 入参、表单三处都没有这些字段。

**改动**：
- `backend/src/types.ts`、`frontend/src/prototype-api.ts`：`TradeDocument` 增加 `condition / warranty / leadTime`
- `backend/src/routes/trade-documents.ts`：`documentBodySchema` 增加三字段
- `frontend/index.html`：单据表单增加三个输入框（产品状态 / 质保 / 交货周期）
- PO 模板：三个单元格渲染实际值；`collectDocumentDraft` / `fillDocumentEditor` 双向映射

**验证**：新建 PO 带三字段 → 保存 → 重新打开，三个输入框完整回填；预览条款区显示 `Brand new / 12 months / 25-30 days`。

### 4. PO 表格排版

**改动**（`frontend/index.html`）：
- 表格统一 `table-layout: fixed`，条款表列宽 15 / 17 / 15 / 31 / 22%，明细表 14 / 44 / 10 / 14 / 18%
- 单元格内边距 6×8 → 7×9，行高 30 → 32，`line-height:1.45`
- 金额列右对齐 + `tabular-nums`；数量列居中；描述列顶对齐（多行描述不把金额挤歪）
- 表头长标题允许换行（原先 `TOTAL AMOUNT (USD)` 被裁成 `TOTAL AMOUNT (USD`）
- 明细隔行浅底纹，长描述 `word-break: break-word`

**验证**：截图核对——表头完整、五列对齐、合计行右对齐、描述换行不压线。

### 5. Description 合并为自由栏位

**改动**：
- 商品明细去掉「材质 Material」「后处理 Finish」两个输入，改为整行宽的「描述 Description」文本域（`span 7 / HS Code span 3 / 数量 span 2` 排满 12 列）
- 类型与入参：`TradeDocumentItem` 增加 `description`（material / finish 保留，只为读历史单）
- PO / PI 模板：`description` 优先；老数据自动把 material · finish 拼成一段（`itemLegacySpec`），不会出现空框
- 切换类型时保留 HS Code 独立字段

**验证**：明细区截图（描述整段可写、HS Code 10 位完整显示）；PI / PO 预览均显示「品名 + 描述 + HS」。

### 6. 新建单据数据残留

**根因**：`openNewDocument` 没有重置「关联客户 / 数据源」两个下拉；`switchDocumentType` 只改标题和编号，其余字段与明细原样保留。

**改动**（`frontend/src/prototype-api.ts`）：
- 新建：清空关联客户、数据源归 `manual`、按默认配置重建表单
- 切类型（侧栏 PI/PO 或页签）：若当前单据不是目标类型 → 重建空白表单；把「转成另一种单据」留给「生成其它单据」按钮，不再由切页签顺手完成

**验证**：新建后 buyer / 描述 / 条款全空、标题与编号按类型重建；已保存 PO 打开后点侧栏 PI → 空白 PI；再点 PO → 空白 PO。

### 复验中发现并修掉的两处

1. **单据审计漏字段**（`backend/src/routes/trade-documents.ts`）：`auditFields` 清单里没有 `condition / warranty / leadTime`，改了质保期、交货周期不会留任何修改痕迹。合同条款类字段必须可追溯，已补进清单。
2. **PO 的 `Item Number` 列被 HS Code 顶替**（`frontend/src/prototype-api.ts`）：原取值是 `model || hsCode || 行号`，没填型号时这一列显示 `9405420000`，列名与内容不符，且描述里已拼过 `HS 9405420000`，重复。改为 `model || 行号`（无型号时显示 `01`），HS Code 仍在描述里独立呈现。
