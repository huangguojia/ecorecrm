输入框体检评分与精致化

对象＝全站所有文本输入框、下拉框、文本域（含页面内、弹窗内、表格内联）。 用 CDP 遍历 32 个页面视图 + 12 类弹窗，逐个量「计算字号 / 字重 / 框高 / 圆角 / 占位符颜色 / 聚焦环」， 共 372 个控件；并单独检查「Hint（占位提示）点击后是否消失」。 改前数据由 INPUT_REFINE=off 摘掉新样式块实测得到，与「改后」同一份代码、同一机位。

结论一句话体检结果

字号档位8 → 3档 改前 10 / 11 / 12 / 13 / 13.3333 / 14 / 16 / 18px
圆角档位8 → 1档 改前 7px / 8px / 6px / 0px / 3px / 12px / 10px / 9px
占位符（Hint）颜色3 → 1套 改前含浏览器默认灰 rgb(117,117,117)
文字撑满框（>0.45）118 → 11个 其中严重撑满（>0.55）18 个

「土」的根因有三：①输入框根本没有字号规范——CSS 里 78 条规则各写各的， 实际渲染出 8 档；<select> 和 <textarea> 甚至从没被设过字号， 直接吃浏览器默认的 13.33px，而 <input> 继承到 16px，同一个弹窗里三种大小。 ②文字和框一样高——框高普遍 27~32px，却塞 16px 的字，占比 0.5~0.7，像「勒住」的。 ③Hint 不像 Hint——占位符是浏览器默认深灰，和已填内容几乎一样重；而且全站没有任何一条聚焦规则让提示消失， 点进去提示还赖着，用户会以为里面已经有字了。

评分逐界面评分表（改前口径）

字号分＝「同界面控件字号是否统一、有无 9/10px 或 16px 离群值」；颜值分＝「圆角种类 + 文字撑满程度 + 离群字重」。 两项取低者为定级。

规范统一后的规则

唯一真相放在 frontend/index.html 尾部的 <style id="input-refine">。新增界面把选择器补进对应分组即可，不要另起一套。

① 字号只有 3 档

常规 13px/400（= --fs-sm）· 高密度表格内联 12px · 标题型 14px/600。 其余 78 条历史规则一律作废（用 !important 是刻意的：字号必须只有一个来源）。

② Hint 点击即消失

占位符一律 #94a3b6（视觉重量明显低于正文）， 聚焦即 color: transparent ——「如果是 Hint，点击后就应该消失」。失焦自动回来。

③ 圆角只有 1 种

全部统一 --radius-sm = 6px。复选框 / 单选 / 滑块 / 文件 / 取色不吃圆角。 唯二例外：登录页（独立一屏，保留 12px 柔角）、备注标题（只有一条底线）。

④ 聚焦环归一

改前全站 41 条聚焦规则、6 套互不相干的光环色（teal / 各色 hex / 不可见）。 现在一律 var(--brand) 描边 + var(--brand-ring) 光环；语义色（单证缺字段红）除外。

Hint「点了不消失」是怎么修的（含实证）

  • 占位符本身：加 :focus::placeholder / :focus-visible::placeholder → 聚焦即透明。 改前全站 0 条这样的规则。
  • 把提示写进 value 的地方：备注页标题无选中时执行 titleEditor.value = "暂无备忘"， 这不是 Hint 而是真值 —— 点它当然不消失，也不能编辑。已改为 value = ""，走原生 placeholder （输入框本来就有 placeholder="选择或新建备忘"）。
  • 下拉框的「请选择」：这类是首项占位，不是 Hint，不去动它（点了会正常选中）。
实证结果：39 / 39 通过。用 design-preview/verify-hint.mjs 在真实浏览器里逐个 focus() 后读 getComputedStyle(el,'::placeholder').color —— 失焦时全部为 rgb(148,163,182)，聚焦后全部变为 rgba(0,0,0,0)（透明）。 覆盖客户 / 线索 / 产品 / 设置 / 个人主页 / 备忘 / 技能库 / 搜客清单 / 搜客雷达 9 个视图。
  • 两点方法论坑（否则会误判成「没生效」）： ① headless Chrome 的窗口没有系统焦点，:focus 根本不匹配（虽然 document.activeElement 是对的）—— 必须开 Emulation.setFocusEmulationEnabled； ② 折叠的 <details> 里的控件压根拿不到焦点（focus() 是空操作）， 但 getComputedStyle 照样返回值 —— 这类要单独排除，否则永远「失败」。全站共 5 处属此类 （搜客清单的开发信面板、搜客雷达的链接框、技能库的调试指令框）。

附带顺手发现的两处问题

① 线索页的「新增线索」按钮点了没反应。 index.html 里 #leadNewButton 和它下面的 <form id="leadCreateForm" class="lead-create-form is-hidden"> 在整个 src/ 里没有任何引用（全站搜 leadNewButton/leadCreateForm 均无命中）， 点击不会出现表单。这是既有问题、不是本次改动引入 —— 已实测确认，等你确认后再决定是接线还是摘掉按钮。
② 「文字撑满」的两个残留是误报。 待办中心·快速新增 和 搜客雷达·候选业务方向 这两处量出来是 0.67~0.72， 但它们的 <input> 是无边框透明内联字段（border:0; background:transparent， 高度 18px 只是文字行高），真正视觉上的框是外层的 42px 药丸 / 表格单元 —— 文字占比其实是 30% 左右，属正常。
